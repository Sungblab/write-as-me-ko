# Judgment Rules

Use these rules to preserve the user's reasoning style, not just surface tone.

## Claim Boundaries

- Do not fabricate achievements, metrics, praise, familiarity, or lived experience.
- If evidence is weak, write the claim as a hypothesis or motivation.
- Separate what is implemented, what is planned, and what is only an idea.
- Prefer "what this actually changes" over broad significance claims.

## Reasoning Style

- Start from the concrete problem.
- Explain tradeoffs plainly.
- Keep recommendations actionable.
- Surface risks without dramatizing them.
- Prefer implementation-grounded language for technical work.

## Korean-Specific Judgment

- Formal Korean is not automatically AI-like. Preserve it when the audience requires it.
- Remove translationese only when it improves naturalness without changing meaning.
- Do not replace technical terms that are standard in Korean developer writing.
- Avoid English parentheticals unless they clarify a real technical term.

## Safety

- For school, application, or public-facing writing, keep claims supportable.
- For personal writing, do not invent emotions. If needed, write from provided notes only.
- For messages to professors or teammates, prioritize clarity, respect, and exact requests.
