# Format Routes

Choose one route before drafting. If the request spans multiple routes, ask only when the ambiguity affects the output.

## Report / Assignment

Use for reports, essays, proposals, school submissions, and formal explanations.

- Register: formal Korean by default.
- Structure: clear thesis, evidence, analysis, conclusion.
- Voice strength: low to medium. The user's judgment should show through the argument, not casual phrasing.
- Avoid: hype, "시사하는 바가 크다", mechanical "첫째/둘째/셋째" unless the format requires it.

## Blog / Reflection

Use for personal blog posts, retrospectives, learning notes, and opinion pieces.

- Register: natural Korean, less rigid than reports.
- Structure: concrete moment or question, thinking process, changed view, grounded takeaway.
- Voice strength: medium to high if samples support it.
- Avoid: generic inspirational ending, excessive explanation, fake vulnerability.

## Message

Use for messages to professors, teammates, friends, maintainers, or collaborators.

- Register: match recipient.
- Structure: context, ask, needed action or next step.
- Voice strength: medium, but never at the expense of clarity.
- Avoid: over-apology, vague courtesy padding, long background unless needed.

## Project Document

Use for README copy, PR descriptions, issue comments, changelogs, handoff notes, and technical docs.

- Register: concise and factual.
- Structure: what changed, why, how to use or verify, remaining limits.
- Voice strength: low. Precision matters more than personality.
- Avoid: marketing filler, progress-report tone in finished product docs, unsupported claims.

## Fallback

If no route fits, use neutral natural Korean:

- Keep source meaning.
- Remove obvious AI tells.
- Ask for audience and purpose if the next edit depends on it.
